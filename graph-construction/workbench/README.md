# AgentCM 本地实验工作台

把轨迹预处理、轨迹切分、谓词发现、轨迹浏览、人工审核、研究任务与 Prompt 编辑放到同一个本地网站。

## 启动

macOS 推荐双击项目根目录的 [打开 AgentCM 工作台.command](../../../打开%20AgentCM%20工作台.command)，也可以双击本目录的 `open-workbench.command`。入口在终端中启动工作台，然后打开浏览器。**保持这个终端窗口打开，网站就会一直运行。** 入口通过相对路径链接到本模块，可随整个项目目录一起移动。

关闭网页、刷新或切换标签页都不影响工作台和实验。**关闭启动它的终端，或在其中按 Ctrl+C，才会停止服务和运行中的实验。** 已保存的实验进度保留，下次打开后可以继续。重复点击入口会复用原服务，并提示保持原来的启动终端打开；新打开的重复窗口可以关闭。

服务停止时，请再次双击项目里的入口。默认启动直接由终端运行，入口会移除该工作区旧的 `launchd` 注册；旧服务还有运行中或等待审核的实验时，提示先完成或停止它。网站只监听 `127.0.0.1`，本地健康检查直接连接回环地址。

首次在项目根目录安装快捷入口：

```bash
./open-workbench.command --install-shortcut
```

可用 `--status` 查看状态，`--stop` 停止服务及运行中的实验，`--no-open` 在当前终端运行服务并自行访问网址。支持 `--port` 与 `--data-dir`；端口被其他应用或工作区占用时显示具体原因。服务消息显示在启动终端中，实验日志保存在各实验目录的 `worker.log`。

### 命令行启动

macOS / Linux，Python 3.11+；运行网站只使用 Python 标准库与浏览器。

```bash
cd graph-construction/workbench
python3 run.py
```

打开 <http://127.0.0.1:8765>。使用 `--port 8766` 更换端口，`--data-dir /absolute/path` 指定独立工作空间。命令行同样保持运行，直到 Ctrl+C 或关闭终端。一个数据目录同时由一个服务管理。高级用法中，显式传入 `--idle-timeout` 才会启用旧的按网页开关模式；`--startup-timeout` 仅在该模式下生效。

本机系统 Python 受 Xcode 环境影响时，可使用已安装的运行时：

```bash
/Users/tianyu/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 run.py
```

## 第一轮实验

1. 在“数据集”选择 `terminal-bench-2.1`，可在“官方任务”和“执行轨迹”之间切换；已接入覆盖 89 个任务的 91 条公开执行轨迹。
2. 在“新建实验”选择“轨迹预处理”，勾选规则和轨迹，保存草稿后对照处理前后内容。运行完成后可点击“基于此结果创建切分”。
3. 点击“创建切分实验”，选择一次已完成的预处理结果及其中的轨迹。选项显示实验名称、轨迹数和编号。填写每窗口核心事件上限、重叠事件数，查看窗口长度分布预览，再填写前文/后文摘要 Token 上限。四项字段均由用户填写，保存草稿时冻结上游来源、所选输入、参数与摘要 Prompt。该数据集没有已完成的预处理结果时，先完成预处理。
4. 点击“开始运行”生成窗口，检查事件范围、上下文和切分统计。两项摘要上限均为 0 时本地执行；开启摘要时先配置模型设置，运行时产生模型用量。
5. 切分完成后，点击“基于此切分发现谓词”。想先试一两个窗口，可以点“取消全选”，展开任务后逐个勾选窗口；也可以全选或按任务勾选。页面显示已选数量，处理上限随选择调整。填写批次审核间隔与研究问题后保存草稿。
6. 配置模型、API Base URL 和 API Key，启动谓词实验，发送所选窗口、Prompt 与定义库，产生模型用量。
7. 到批次边界后，在“谓词审核”检查定义、参数、成立/排除条件和对应窗口。保存意见后，提交批次反馈继续。
8. 对比预处理或切分实验的参数与统计，或对比谓词实验的定义库，把后续问题记入任务看板。

最后一批按已有发现流程直接完成；网页继续支持保存审核意见。运行中可停止，失败或停止后可恢复到已保存阶段。

### 谓词审核

谓词名称、完整定义、参数说明、成立条件和排除条件直接显示英文原文，可按名称或定义搜索。页面直接读取实验结果，查看和审核过程中不调用翻译模型。审核意见单独保存在本地；英文定义变化后，相应意见会标记为需复审。

### 直接查看执行过程

三类实验详情页都在进度卡片下面显示“执行过程”。谓词发现会显示当前任务、第几个窗口，以及“发现候选谓词 → 与已有谓词比较 → 模型审核谓词 → 保存结果”。日志逐行记录请求发出、结果返回、格式检查、失败重试、窗口保存、等待人工反馈和运行结束。

页面可见且实验运行中时，每 2 秒读取一次进度；等待模型返回时显示等待时间，其他运行阶段显示本次运行时间。向上翻日志会暂停跟随，勾选“跟随最新记录”回到底部；刷新后可继续查看已保存日志。停止、失败和完成后显示相应状态。

`workbench/execution_progress.py` 负责记录当前步骤，写入实验根目录 `execution.json` 并输出带时间的 `worker.log`。算法的阶段快照继续用于恢复运行。旧实验从原有执行状态与日志显示进度；正在运行的旧服务可以立即加载新的界面，重新启动服务后会读取新增的精确步骤和等待计时。

### 实验管理、返回与回收站

实验列表每行提供“查看”和“删除”。预处理、切分、谓词发现详情页顶部统一提供“返回实验管理”和“删除实验”；返回时保留本次页面会话中的搜索词与数据集筛选。

删除确认后，实验移至回收站，从活动列表、计数和新实验来源选项中移出。回收站可恢复实验及原状态，输入、结果、编号映射、审核记录和已有任务关联继续保留。已创建的后续实验使用自己的输入快照，可继续运行。运行中或等待反馈的实验需先停止再删除。

后端在实验目录写入 `deleted.json` 标记，恢复时移除标记。默认读取/运行接口拒绝访问已删除实验；回收站接口为 `GET /api/experiments/deleted`、`POST /api/experiment/delete` 和 `POST /api/experiment/restore`。生命周期逻辑集中在 `workbench/experiment_lifecycle.py`，确认/恢复界面集中在 `web/experiment-management.js`，共用返回栏与列表操作在 `web/core.js`。

### 轨迹预处理与前后对照

新建预处理实验首先执行 `execution-record/v5` 记录筛选，再进行字段精简：

- 排除因环境/运行器故障中断的执行。整条轨迹只要有工具调用或非空 agent reasoning 就保留；两者都没有时排除。重跑遵循相同规则。默认 `selection_mode: all`，保留其余成功、任务失败、无有效评分与结果未知的执行。同一任务的不同尝试分别保留；保留轨迹内部的思考、报错、修正和工具调用保持完整。
- 只去除重复导入的相同记录：在字段精简前，对完整 JSON（包括 query、events、结果、执行轮次与来源 metadata）排序对象键并计算 SHA-256。文件名、缩进和对象键顺序不影响判定，事件顺序与正文参与判定。相同内容保留轨迹 ID 字典序最小的一份；来源或执行元信息不同的记录分别保留。
- “执行结果范围”可选 `success_only`，仅保留 `metadata.result.pass == true` 且 `scored == true` 的执行；同任务的多条成功尝试仍分别保留。
- 环境/运行器故障与无工具调用独立标记，可同时出现。当前导入格式中，`scored: false` 且 `errorCode: command_exec_failed` 标记环境/运行器故障；所有事件的工具调用总数为 0 标记无工具调用；其中有非空 agent thought 的轨迹按 reasoning 内容保留。清单显示工具调用数和 reasoning 数。单纯评分失败、缺少评分或某次工具报错不产生环境故障标签。标签随筛选清单保存，不写进事件正文。每条排除记录只计一次主原因，优先级为重复导入、环境故障、没有可建模内容、结果范围。
- 创建前实时显示保留/排除数量、保留结果分布、独立标记计数、每条执行的处理原因及重复导入对应的记录。轨迹选择列表与前后对照也显示结果和标签。`POST /api/experiment/preprocess-preview` 只读计算；空选择或所选结果范围下没有保留项时不能创建草稿。
- 实验保存全部所选输入快照、结果范围与 `selection.json` 清单。运行、恢复和对照验证清单与输入一致，保留项进入 `output/trajectories/` 和后续切分。历史 `execution-record/v4` 继续排除全部无工具调用记录，`execution-record/v3` 继续保留无工具调用记录，`execution-record/v2` 继续保留环境故障记录，`successful-task/v1` 继续按“仅成功、每任务最后一次成功”复现，无 `selection_policy` 的实验继续按原快照运行。

当前全量 91 条记录排除 `prove-plus-comm` 与 `regex-chess` 的首次环境故障执行，默认保留 89 条、覆盖 89 个任务，包括 62 条成功、27 条任务失败。`prove-plus-comm` 的成功重跑保留；`regex-chess` 重跑含 1 个 reasoning、0 次工具调用，也保留。完全相同的重复导入为 0 条，选择“仅成功”得到 62 条。原始日志和数据集文件作为来源继续保存。

预处理输入为数据集中的已规范化完整事件轨迹；原始 OMP 日志到事件的导入转换见 `datasets/adapters/omp.py`。新实验采用 `preprocess-experiment/v1`，字段处理规则版本为 `trajectory-fields/v2`，规则由 `predicate-discovery/src/preprocess/compact.py` 实现。旧 `trajectory-fields/v1` 实验保持原有两项规则，可继续查看、运行和恢复：

- 默认开启工具输出去重：仅当 `observation.content` 是与 `raw` 完全一致的纯文本，且文本块没有附加字段时移除 `content`。图片、混合内容、附加属性和不同文本均保留。
- 可选移出来源行号：移除事件与 observation 中的 `source_line`；输入快照保留原始值用于追溯。
- 可选精简调用标识（`simplify_call_ids`，默认关闭）：按整条轨迹的事件/调用顺序将 `tool_call_id` 替换为 `call-0001` 等唯一短编号，删除调用上的 `source_call_id`。切分与重叠窗口沿用短编号；参数和正文中的同名字段或相同字符串保持原样。
- 保留轨迹的事件 ID、顺序、任务说明、thought、工具参数、输出正文及错误标记保留。全部关闭字段规则可作为字段原样对照组，轨迹筛选继续应用。

轨迹列表提供全选复选框、全不选按钮和已选数量，可清空后只勾选一条做对照。创建时固定所选轨迹与规则；草稿支持逐事件或整条 JSON 的左右对照，并列出变化路径。删除项在处理前以红字、浅红底显示；替换项在处理前后都以黄色标记，悬停查看新旧值。标记按精确字段路径定位。下方可展开调用编号映射，随当前事件/整条轨迹范围切换。运行后展示保存的结果，分别统计删除和替换字段数、改变的事件数、前后长度和减少比例。长度按事件 JSON 字符数 ÷ 4 向上取整估算，任务说明与轨迹元信息另计。预处理使用本地确定性规则；恢复时从固定输入重新生成。

处理后轨迹保存到 `output/trajectories/`，逐字段报告在 `output/reports/`，报告使用 `operation: remove/replace` 区分删除和替换。启用调用标识精简后，逐轨迹编号映射单独保存到 `output/call-id-maps/<trajectory>.json`（`call-id-map/v1`），记录事件、调用位置、短编号及原始两种编号；映射采用列表，保留原始编号重复时的位置区别。映射用于回溯，不拼入后续模型输入。切分只能选择已完成的预处理产物；创建、长度预览与历史空草稿接入均要求 `preprocess_experiment_id`，校验完成状态、所属数据集、结果摘要和轨迹归属。切分保存预处理实验 ID、规则和独立输入副本。`GET /api/preprocess-comparison` 提供只读对照和当前范围的编号映射。

### 窗口长度预览

每窗口核心事件上限决定连续核心窗口的边界，重叠事件数决定向前附带多少完整事件。文本长度只用于统计。新实验采用 `event-count/v2`；旧 `event-greedy/v1` 快照继续使用原算法恢复。

填写两项边界参数后，预览展示预计窗口数、每窗核心事件数分布，以及核心事件与“核心 + 重叠”的 Token 长度分布。事件数直接写成“包含 10 个 agent event 的窗口有 732 个”，旁边说明重叠部分另算。中位数、P90、最大值和最长五个窗口按“核心 + 重叠”统计。Token 使用紧凑 JSON 字符数除以 4 向上取整估算；任务说明、摘要与 Prompt 另计。

前端在参数、轨迹选择或数据集变化后延迟 300ms 调用 `POST /api/experiment/split-preview`，并丢弃已过期的响应。该接口只读取所选完整轨迹，在内存中计算共享的切分边界和统计，无模型调用、实验创建或窗口文件写入。

## 页面与数据

| 页面 | 操作与数据来源 |
| --- | --- |
| 研究概览 | 当前数据集、切分实验、全部实验与任务统计；真实批次中的定义数量变化 |
| 实验管理 | 预处理/切分/谓词三类实验；创建、启动、停止、恢复；前后轨迹、规则、统计与定义库对比 |
| 谓词审核 | 保留/修订/合并/删除意见、参数与条件、定义出现的窗口；定义变化后提示复审 |
| 任务看板 | 从仓库 TODO 初始化；新增、编辑、关联实验、拖动或选择状态、删除 |
| 数据集 | 官方原版任务的说明、配置、类别/难度与文件清单；已有规范化轨迹的事件序列和切分实验 |
| Prompt 工作室 | 编辑九份 Prompt 工作副本、模板变量校验、恢复源码版本；新实验自动快照 |
| 模型设置 | 模型、API 地址、API Key；Key 明文显示，保存和刷新后自动回填；保存后用于新建实验 |

数据统一由仓库根目录的 [datasets/catalog.json](../../datasets/catalog.json) 注册，说明见 [datasets/README.md](../../datasets/README.md)。当前只有官方完整的 `terminal-bench-2.1`，包含 89 个任务和 1,101 个原版文件；工作台按 `harbor-tasks` 格式展示。任务包提供说明、环境、参考解法与验证脚本；另接入 Lottolabs 使用 Qwen3.8-27B / OMP / xhigh 产生的公开执行轨迹，91 次执行覆盖 89 个任务，含两项基础设施重跑。原有 20 任务子集和 19 条预处理轨迹已清理。

数据集可同时浏览原版任务和完整轨迹。新建切分实验要求已有完成的预处理结果；没有可用结果时显示先完成预处理的提示，并禁用创建按钮。历史空输入草稿可通过“接入预处理结果”绑定已完成的上游实验。已有切分输入快照保持固定，可按创建时的内容查看、运行和恢复。

预处理实验采用 `preprocess-experiment/v1`，切分实验采用 `split-experiment/v1`，新谓词实验采用 `predicate-definition/v2`。谓词实验必须选择已完成的切分实验；保存源实验 id、切分参数、输出内容摘要和窗口副本。每个 agent event 展开成 reasoning、action、observation 节点，保存到实验的 `nodes/`。证据页按类型展示正文和调用返回边，运行前核验节点与输入一致；四阶段 Prompt 采用相同类型约束。已有切分可直接创建新实验。工作副本 Prompt 升级时备份到 `prompt_migrations/`，历史实验保留原输入与定义。新建谓词实验用 `window_ids` 明确指定窗口，按源轨迹与窗口编号顺序处理；若填写更小的处理上限，只保存所选窗口中的前几个。空选择、重复编号和不属于该来源的窗口会被拒绝。2026-10-15 按用户要求清理的 RZP 旧关系类型实验保持清理状态。

审核意见按定义内容摘要记录，旧意见在定义变化后提示复审。批次反馈编辑框汇总当前库中内容匹配的审核意见；用户可以修改汇总后提交。定义库由原有模型修订和结构校验流程更新。前端“保存审核”记录个人意见，实验输入与阶段产物由工作台读取。

“定义出现的窗口”根据发现、比较、审核响应中的名称引用关联。窗口详情保留阶段 JSON，便于检查候选被接受、匹配或修订的过程。

```text
│   ├── splitting.py          # 切分快照、参数校验、断点、摘要调用和统计
│   ├── split_preview.py      # 只读窗口长度分布、分位数与最长窗口
│   ├── experiment_lifecycle.py # 可恢复删除、回收站与运行进程校验
│   ├── store.py              # 数据目录、快照、实验进程、审核和任务
│   ├── worker.py             # 独立实验进程、网页反馈桥接
│   ├── execution_progress.py # 当前步骤、请求等待、带时间的执行日志
│   └── server.py             # 本地 HTTP API、静态页面、单实例锁
├── web/                      # 页面、表单、数据集选择、交互与样式
├── tests/                    # 后端集成测试、隔离浏览器测试
└── runs/                     # 本地工作数据，Git 忽略
    ├── settings.json         # 模型配置与密钥，权限 600
    ├── prompts.json          # 当前 Prompt 工作副本
    ├── tasks.json
    ├── reviews.json
    ├── review_history/       # 被后续审核替换的历史意见
    └── experiments/<id>/
        ├── experiment.json   # 名称、研究问题、模型与流程配置
        ├── inputs/           # 预处理/切分：完整轨迹副本；谓词：所选窗口副本
        ├── prompts/          # 对应实验的摘要或谓词 Prompt 快照
        ├── output/           # 预处理：trajectories/、reports/；切分：windows/；谓词：发现流程输出
        ├── feedback_submissions/
        ├── lifecycle.json
        ├── execution.json   # 当前运行编号、步骤、窗口及等待开始时间
        ├── deleted.json     # 存在时处于回收站，恢复后移除此标记
        └── worker.log
```

切分复用 `predicate-discovery/src/split` 的切窗与摘要实现，谓词发现调用 `src/discover_predicates`，每个实验独立子进程。工作台提供编排和界面，谓词协议与发现算法继续由发现模块维护。恢复使用输入清单、阶段保存点和实验内 Prompt 快照；创建后修改工作副本不会改变已有实验。

预处理表单、字段规则和前后对照集中在 `web/preprocessing.js`，轨迹筛选预览与明细集中在 `web/preprocess-selection.js`。前端窗口预览单独放在 `web/split-preview.js`，表单负责参数输入，`web/splitting.js` 负责已保存实验的统计与对比。谓词实验的全选、逐窗口选择、数量及处理上限联动集中在 `web/predicate-selection.js`。

窗口选择验证：`test_predicate_inputs.py` 验证不连续窗口的冻结与实际运行、空选择及非法编号拒绝、数量上限和旧请求兼容。`node tests/predicate_selection_smoke.cjs` 使用隔离工作区验证全选/取消全选、按任务和逐窗口勾选、部分选中状态、数量联动、来源切换、保存结果及窄屏布局。

执行过程验证：`test_execution_progress.py` 验证请求发出前保存等待状态、结果校验重试、反馈修订、失败续跑与本地处理记录。`node tests/execution_progress_smoke.cjs` 用延迟返回的本地模型验证实时步骤、计时、重试、人工反馈、滚动位置保持、刷新、停止状态和窄屏展示。

谓词审核验证：`node tests/predicate_review_smoke.cjs` 验证英文各字段与原始结果一致、保存审核后刷新、英文搜索、JSON 导出、窄屏布局，以及页面不发送翻译请求、翻译接口已移除。

实验管理验证：`test_experiment_lifecycle.py` 覆盖删除/恢复、快照保留、重启读取、进程校验、后续实验独立运行、审核与任务关联，以及写入令牌和路径校验。`node tests/experiment_management_smoke.cjs` 使用隔离工作区与本地测试模型，验证三类详情页返回、筛选保留、取消/删除/恢复、刷新、运行中按钮状态及桌面/移动布局。

服务绑定 `127.0.0.1`，校验 Host、Origin 和写操作令牌。页面按文本展示轨迹内容。本机设置接口返回完整 API Key，模型设置页以明文回填；所有工作台运行数据存入被 Git 忽略的 `runs/`。
